# Agents

## Purpose

The versioned agents that write changes.

## Where

Automation ▸ Agents (`/automation/agents`, an agent at `/automation/agents/:name`)

## What you can do

- While the token budget pauses agents, a banner reads "Agents paused: budget reached · spent of budget tokens · resumes <date> or when an owner raises it". **Raise budget** opens [Needs you](needs-you.md); a person who isn't an owner sees it disabled, with "Only owners can raise the budget: <owners>" and **Ask <owner>** (an email to the first owner).
- An agent the budget pauses shows a `paused · budget` pill and "Paused: budget reached · resumes <date>"; jobs it already holds finish.
- Search agents. The Fleet aside shows running agents, races, tokens and the **Canary auto-promote** toggle.
- **New agent**: a wizard for harness, model (only models with a working credential) and limits, then **Create agent**; **Connect in My model access** when a credential is missing. A harness with no models in the catalog says so.
- Models come from Cloudflare's model catalog, with ids like `@cf/...` (Workers AI) or `<provider>/<model>` (third-party models such as Anthropic's and OpenAI's), filtered by harness: Claude Code lists Anthropic models, Codex OpenAI models, OpenCode any. **Catalog ↗** opens the model's own catalog page.
- On an agent: it opens on **History**; tabs **Runs** (the run's agent@version, per-call model, tokens, cost and latency, **View gateway log**, **View trace**), **History** (each version newest first with its channel, stable or canary, its traffic, its win rate (merged of the changes it ran on that ended merged, failed or closed; the untrusted line under 20 of them) when it was released and who released it (cinder for a baked-in version). The canary's traffic slider sets its share of new runs when you let go of it, and stable shows the rest. **Promote to stable** on the canary and **Roll back to vN** on versions older than stable each ask to confirm, then point stable at that version; Promote warns when the canary has under 20 outcomes. These work for Maintainers and above, on every agent: a new change pins the developer's canary when its id hashes into the canary's share, else its stable version, and each review or resolve job runs the reviewer's or resolver's version picked when it is queued, so runs already going finish on the version they started with. Below the table, **Release history** lists each release, promote, rollback and canary move, newest first, with who made it and when), **Settings & prompt** (picking a model, or **Edit** then **Save draft** on the prompt, saves a draft for the next release; the **Network allowlist** card lists the hosts the next release may reach, and adding or removing a host saves it to the draft, a host pattern of `[a-z0-9.-]` with `*` or `?` wildcards; a saved model the harness can't run shows selected with "Not available for this harness") and **Races** (each leg won, lost or pending until the race has a winner). Runs · 24h counts every run with AI Gateway calls in the last 24 hours, the same calls the tokens and cost tiles sum. Each call row is one AI Gateway log with a model, pulled every 10 minutes: its model, input and output tokens, cost and duration as latency, grouped into the run its metadata names (the job, else the change).
- The harness is Claude Code, Codex or OpenCode, the ones the runner implements; a draft with any other harness is refused (HTTP 400), and a runner fails a job whose harness it doesn't implement with "harness <name> isn't supported by this runner" instead of running another one.
- **A version**: a version's `name@vN` on History (and on Runs and Races) opens it there (`?v=N`): its lock (model, harness, effort, tools, limits, egress, web) and its prompt, rendered as Markdown with a **Raw** toggle, both read from its release tag (`GET /api/agents/:name/versions/:version`). It opens with the diff from the version before it (the first version has none). **Compare with…** picks another version and shows the prompt and lock diff between them (`&vs=M`). **Edit from this version** saves that version's prompt and lock as the draft (asking to confirm when a draft is already saved) and opens Settings & prompt; releasing it makes a new version and leaves the old one as it was.
- A draft whose model the harness can't run is refused (HTTP 422).
- **Marketplace agents**: an agent installed from the marketplace has a locked prompt. Settings & prompt shows it read-only with "Installed from the marketplace; its prompt is locked." and no **Edit**; a draft that changes the prompt is refused (HTTP 409, `prompt_locked`). Model, limits and the network allowlist stay editable.
- **Draft card**: while a draft is saved, Settings & prompt shows `<name>@v<next>-draft`, "Draft saved · <time> ago", "not running anywhere" (no channel points at a draft, so no job runs it), and its diff to the shown version (stable, else the newest) for the prompt and every changed lock field. **Discard draft** deletes it after a confirm (`DELETE /api/agents/:name/draft`). **Release v<next>…** picks **canary** (replaces the current canary at its share) or **stable** and an optional note (up to 500 characters); `POST /api/agents/:name/release {channel, note}` queues the release, which tags `agent/<name>/v<next>` and points that channel at it once it lands. The queued release carries the draft, so the saved draft is cleared.
- **Canary share**: `PUT /api/agents/:name/channels/canary {version, share}` (owners) sends `share`% (0-100) of changes to the canary: a hash of the change id picks them, so a change always gets the same answer, and each review or resolve job records the version it picked when it is queued. `GET /api/agents/:name/versions` lists each version with its channel, the canary's share, its release time and its outcomes (merged of the changes it ran on that ended merged, failed or closed; trusted from 200). `GET /api/agents/:name/history` lists its releases and channel moves, newest first.
- **Auto-promote**: when a change ends merged, failed or closed, its outcome is scored against every agent version its jobs ran. With **Canary auto-promote** on, a canary with at least the repo's trust threshold of outcomes (200 by default) and a merge rate at least stable's becomes stable, its share resets to 0, and an `agent_promoted` outcome records it. A canary that has won 60% of at least 30 decided races is promoted the same way. Either promotion shows in **Release history** as a promote by `auto-promote`.
- Agents never receive Keystore secrets: an agent job's claim carries none, and releasing a draft that declares `secrets` is refused (HTTP 422, `agents_get_no_secrets`).
- Allowing or denying an egress host (`POST /api/agents/:name/egress`, owners only) releases a new version: a copy of the version the chosen channel points to with the host added to or removed from its egress allowlist, and the channel moves to it once the release lands.
- **Web**: each version reads the web as `markdown` (the default for new versions) or `raw` (`web: raw` in its `agent.yml`; versions released before the setting are `raw`). The setting is part of the version's lock and shows in the draft card's diff (`-web: raw` / `+web: markdown`). On `markdown`, an agent's allowed GET requests ask sites for Markdown; an HTML answer is converted to Markdown before the agent reads it, and anything else passes through unchanged. The allowlist and audit mode apply first, so a denied host is refused before any conversion. The Versions tab's **Web** column shows each version's setting and, once its jobs have had pages converted, how many and the bytes that saved.
- At run time a version's prompt is the harness's system prompt, with the change's intent as the task; a version with no prompt runs without one. Its **Max spend** is the run's budget: once the run's model usage goes over it the harness stops and the job fails with "max spend reached".

## Backed by

Agent versions are tags in the `cinder-agents` Artifacts repo, indexed in D1. Web conversion runs in the container egress with Workers AI, counted per job in D1. Committing or pushing to that repo needs a role with `agent.release` (Maintainers and above), and a version tag counts as a release only when cinder wrote it or a release job pushed it; the model catalog is Cloudflare's AI catalog API, cached in D1 for a day; model calls and run detail come from AI Gateway.
