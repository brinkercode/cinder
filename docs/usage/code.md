# Code

## Purpose

Browse, edit and commit the files of a repo on the target branch, or on a change's workspace.

A branch or tag name with `/` (`release/1.2`, `feature/x`) opens the same way, whether the link encodes it (`release%2F1.2`) or not; the address then shows the encoded form. A link opens its file without waiting for the branch list.

## Where

Code ▸ *repo* ▸ Code (`/:repo/code/:ref/*`)

## What you can do

- Pick the target branch from the branch menu in the top bar (press **B**). Each row shows the branch, its role, `↑ahead ↓behind` the default branch and a check on the current target; ↑/↓ move through the rows, Enter picks one, Esc closes the menu. **All branches** and **New branch** open the Branches modal, whose search filters the list. The menu and modal list every branch and tag in the repo's git (tags in their own section), read once the page is idle and again each time they open, while the last list stays shown; until the first list arrives the menu shows "Loading branches and tags…". Find a branch hides sections with no match and reads "No branches match" when nothing does. On Code the menu's Change workspaces lists the repo's draft changes by id and title.
- **Releases** in the toolbar, between search and **Add file**, opens the repo's [Releases](#releases). Its chip shows the newest tag, read once the page is idle so the toolbar never waits on it; a repo with no tags shows the link with no chip, and the chip is hidden below 1100px wide.
- **Search code**, and **Find a file** in the Files tree. Search lists up to 200 lines holding the text (any case) as `path:line`, each line once, read from a D1 index of the files at the ref's head. Pushes and commits update the index (a commit's update finishes just after the commit is saved, so a search straight after it may miss its lines); a ref with no index yet (just imported, say) is indexed on its first search.
- Open a file and switch between **Code**, **Blame** and **History** (a markdown file shows **Preview**, **Source** and **History**, opening on **Preview**). The file card's header shows the path, the line count, the view switch, **Edit** and a copy-file button; the view is kept in the address (`?v=`). Switching files keeps the toolbar, tree and file card in place and changes only the file body: a file already read swaps in at once; while another loads, the address, the tree's selection and the heading move to it at once and the previous file stays, dimmed, until it lands. Switching views loads nothing. The content shows as soon as it arrives; **Blame** and **History** load after it, and so do open changes, leases and symbols the first time a repo and branch open. Those are read once and reused while the page is open, so a file switch fetches only the file. Code colours a file with the editor's grammar and theme once the editor has loaded, just after the file shows (until then comments, strings and keywords are coloured in common languages), so a file looks the same in Code and in **Edit**, with the same font, gutter and padding; the line numbers sit 16 px from the code in both. **History** lists the file's commits with author and age. **Blame** shows each hunk's author, change and age. Files, the tree and the commit list already read stay in memory while the page is open, so going back to a file makes no request; a commit drops them, and a repo event reloads the tree and commit list only when the branch's head commit moved (open changes, leases and symbols reload on every event). Neither the file nor a commit's diff waits for the Commits card, which fills in when its log lands; a commit's diff is read alongside the file. Until the blame job has run for a file, **Blame** says it is not computed yet and queued.
- Markdown (a README, a markdown file's **Preview**, wiki pages and release notes) renders headings, bulleted, numbered, nested and task lists, quotes, tables, rules, images, links, bold, italic, strikethrough and fenced code, which is coloured by the fence's language (`js`, `bash`, `yaml`, …) once its grammar loads. Raw HTML a README uses for layout (`<p align>`, `<img width>`, `<details>`, `<kbd>`, `<br>` and similar) renders; scripts, styles, event handlers and unsafe links are dropped. In a repo's markdown, relative images show the file from the repo and relative links open the file in Code, resolved from the markdown file's folder.
- On the repo root, **Active in** *repo* lists up to 3 changes holding leases, one row each (its symbol lease before a file-level one), by change title, holder, file and symbol; **See all** opens Changes. A file has no rail, so the code takes its width: its lease state is a chip in the file header, a green **Free to edit** or *n* **leases** with a dot per holder (red while a collision warning is up). The chip opens **Live on this file**, which lists the same way, one row per change. The holder is the agent driving the change, named and versioned from the runner's claim or the agent picked on New change ("agent@pending" until either names it), or the person who took it over; lease bands and tree dots take the holder's colour. On a file, a holder that wrote a symbol in the last 10 minutes also reads "editing now", and another change writing a symbol the holder leases shows as a live warning in a banner over the code ("<change> is changing the signature of <symbol>, which <holder> leases") without a reload.
- **Edit** opens Monaco in place of the code, with no layout shift: the same font, colours (no bracket or match highlighting), lease strips and bands, so no line moves. The editor follows the file's length, up to 560 px. It starts loading when a file opens, or when you hover or focus **Edit**. Under it, a **Message** becomes the change's intent, and **Where it goes** picks one of: **Open a change · you drive** (the default; reviewers approve, the verifier merges, agents don't push to it unless you let them), **Hand to an agent** (your edit is the starting point, the message the intent; **Hand to agent** creates the change and opens it, and stays disabled until there is a message, with "Add a message: it becomes the agent's intent" in the bar), or **Commit directly to** *branch* (unavailable on integration branches, with the reason shown; in a workspace, **Commit to workspace** *change*). When an agent holds a lease on the file, a note says your change waits for it or asks its holder to hand over. The bottom bar shows what changed ("3 lines changed", "Renamed" or "No edits yet"), **Cancel**, **Stage** and the primary button, labelled for the destination and disabled until there is an edit and a message. While editing, the header shows the file path as an editable field (edit it to rename or move the file; it suggests the repo's folders), an **Editing** pill, **Stage delete** and **Cancel** in place of the view switch and **Edit**, and the card border takes the brand colour. **Cancel** or Escape (outside a dialog or popover) returns to the file's view at the same scroll position; with unsaved edits (text or a new path) it first asks in the page, "Discard your edits to *file*?", to **Keep editing** or **Discard**. When **Open a change** is chosen and the edit touches a symbol another change holds (a rename touches every symbol in the file; a lease on the whole file bands every line, so any edit, rename or delete of it touches it), the button opens a prompt above the bottom bar instead: the symbol and its lines, the holder and its change, and when the lease expires. **Stack on** *change* waits, then rebases after it merges; **Run in parallel** lets both go ahead and shows p(collision) with its judge's trust ("untrusted: n outcomes" until calibrated); **Send to the lease holder** asks it to hand the lease over. **Continue** opens the change in that mode; **Back to editing** closes the prompt. After a send the prompt shows "Waiting for *change* to answer" with **Cancel request**: when the holder hands over, the change opens holding the lease; if it declines, the prompt shows its reason with **Stack** or **Keep editing**; if it doesn't answer before the lease expires, the change stacks. A proposed edit is committed by a worker; the new change shows "Committing your edit…" until it lands.
- Code is highlighted in about 240 languages with TextMate grammars, the same in View, Blame, Edit and change diffs, in light and dark. The language is picked by file name (`Dockerfile`, `Makefile`, `Jenkinsfile`, `CODEOWNERS`, `.gitignore`, `.bashrc`, `.env*`, `go.mod`, `Gemfile`, `BUILD`, `CMakeLists.txt`, `nginx.conf`) or extension; anything else is plain text. Keywords, strings, comments, builtins, function names, types, numbers, operators, punctuation, tags and attribute or key names each have a colour from the app's theme. A language's grammar loads the first time a file in it opens; until then the code shows a lighter highlighting.
- Add a file by path and **Commit new file**, or **Upload** files. Staged files show in a **Staged** card above the file, one entry per path (staging again or renaming replaces it), each with its old path for a rename, an add, edit, rename or delete tag and **Unstage**, and an `M` or `D` mark in the tree; **Open change · n files** submits them together with a message as one commit on a change you drive, which then verifies on that commit (a staged edit, rename or delete that touches a symbol another change holds first shows the same lease prompt as **Edit**, and the choice is sent with the new change), and **Discard all** empties the card. Leaving the branch with staged files asks to confirm; a commit refused because someone committed first reads "Someone committed first; reload to rebase your edit". Owners and anyone whose role grants write access to the repo can commit. A commit onto an existing integration branch (such as `main`) is refused, for owners too, with "*branch* is an integration branch; open a change to land on it": integration branches change only through a change.
- **All commits** lists the branch's commits, 10 a page, with the same pager as the Commits card. **Clone** opens the clone popover: the HTTPS URL with a copy button (a toast confirms; if the browser blocks the clipboard, the URL is selected to copy by hand), how to push a branch, how to propose straight from git with `git push origin HEAD:refs/for/<target>` (it opens a change on `<target>` that you drive, verified on the pushed commit; no agent develops it). **New change** opens the change composer.
- The clone popover shows `cinder repo credentials <repo>`: run it with the `cinder` CLI to get a write token for the repo, valid 10 minutes: enough to clone and push. Git asks for a username and password: type any username and the token as the password. Behind Cloudflare Access the CLI also works with only an allowlisted Access service token: set `CINDER_URL`, `CINDER_ACCESS_CLIENT_ID` and `CINDER_ACCESS_CLIENT_SECRET` (`CINDER_TOKEN` is then optional). The browser never receives a git token: a request signed in only by the browser's Access cookie is refused; a request signed in by a bearer token or a service token gets one. Only owners and people whose role grants write access to the repo get one; anyone else is told they need write access. An archived repo issues no token (409 `archived`), and a push made with a token issued before the archive is put back.
- An empty repo opens on **Quick setup**: its clone URL with a copy button and the `cinder repo credentials <repo>` command for a push token, copyable commands to create a new repository or push an existing one to the default branch, and **Create a README** (prefilled) or **Add a file**, which open the new-file editor. Committing the first file creates the default branch and leaves Quick setup. The first push to the default branch lands directly; after that work arrives as changes on `refs/for/<default branch>`.
- Push a branch with `git push origin <branch>`. It appears in the branch menu and the Branches modal within seconds. To merge it, open **New change** and pick the branch as head; each later push to that branch re-verifies the open change.
- The protected branches (the default branch and the policy's integration and release branches, such as `main`, `develop` and `release/*`) take no direct pushes: a push to one is rolled back to its previous commit, and a new protected branch is deleted. While a merge runs on the branch, only the merge's own commit (one whose tree the merge's verify checked) is kept. They change only through a change and the verifier.
- On a change workspace, a strip above the files shows the agent, the workspace, what it is editing and the symbols it leases. **Release lease** frees the lease at once and pauses the agent (refused with the reason while the change is mid-commit); **Give it back** hands the change to its agent again and re-grants the lease. **Message agent** sends a line the agent reads with its next step. **Take over** the change from its agent. Change ids on the page and in the branch menu show their first 8 characters; the tooltip and a copy carry the full id.

### Releases

`/:repo/releases`, from **Releases** in the toolbar: tags and releases for the repo, and where each release is live. The page bar starts with a `Code › Releases` breadcrumb; **Code** goes back to the repo's Code.

- On a repository with no code: an empty state with **Quick setup** (opens Code) instead of the page's data.
- Search tags and releases; show All, Drafts or Published. A search with no matches shows "No tags or releases match".
- **New tag**: names the tag and picks the existing commit it tags (no new commit or branch). The name field shows the semver form and the latest tag; a name that already exists is flagged as you type ("… already exists, at *sha*. Tags can't move") and Create is disabled. The commit comes from **Recent on a branch** (a branch, then its recent commits with SHA, message and age) or **Paste a SHA** (7 to 40 characters, resolved against every branch of the repo, or an error). The message is optional. A failed create shows its error inline and creates nothing. The tag gets its own card at once, with a "Tag … created" confirmation. A tag without a release keeps that card (shown under All) until a release is drafted on it.
- **Draft release** with markdown notes (Write and Preview tabs). Preview and the release card render the same markdown as a README. The card shows the release title.
- **Publish** a draft. A published release keeps the commit its tag pointed at when it was published, and a promote deploys that commit. A git push that moves or deletes a tag with a release is put back. A git push that deletes a tag without a release removes its card.
- A release reads "Live in" with a chip per environment whose current successful deploy runs its commit, however it got there; each chip opens [Environments](environments.md). Releases are promoted from Environments; a published release live nowhere shows a **Promote in Environments** link.

## Backed by

Artifacts (the repo's git storage), with tags, authorship, symbols and the code search index in D1. Each branch's head and the tree, files and history read at a commit are kept in the repo's Durable Object, so a page opens with one tree request and the file read alongside it. Pushes reach cinder as Artifacts push events on the `cinder-events` queue. The page's **Backed by** link opens the Artifacts repo.
